# LazyRef PUR Viewer

PureRefの `.pur` をObsidianで開き、画像の追加、削除、配置編集と保存ができるプラグインです。
現行版は **v0.18.1**。
対象はコンテナー **2.1 / DB200101** で、旧形式1.10や未知のDB世代は未対応です。
Canvasへの事前変換や画像の外部抽出は不要です。

## 導入と更新

Obsidian 1.8.0以降が対象です。
コミュニティプラグイン一覧には未登録のため、手動で導入します。

リポジトリのルートでビルドします（Node.jsは開発時のみ必要）。

```powershell
npm --prefix obsidian-pur ci
npm --prefix obsidian-pur run build
```

`obsidian-pur\dist\` の次の4ファイルを、保管庫の `.obsidian\plugins\lazyref-pur\` にコピーしてください。

| ファイル | 用途 |
|---|---|
| `main.js` | プラグイン本体（HEICのWASMとWorkerも内包） |
| `manifest.json` | プラグイン情報 |
| `styles.css` | 表示スタイル |
| `THIRD-PARTY-NOTICES.txt` | ライセンス表示 |

`HEIC-SOURCES\` も配布物と一緒に保持し、再配布時は必ず同梱してください。
対応ソースと再ビルド手順のフォルダーで、実行時には読み込みません。
本体は約6.75MB、対応ソースを含む配布物は約12.9MBです。
別の `.wasm`、Workerファイル、`node_modules` は不要で、実行時のNode.js、外部実行ファイル、CDN、通信に依存しません。

Obsidianを再起動し、「設定」→「コミュニティプラグイン」で「LazyRef PUR Viewer」を有効にしてください。
保管庫の `.pur` をクリックして開きます。
開かない場合はファイルの右クリックから「Open with LazyRef PUR Viewer」を選びます。
同じ拡張子を扱う別プラグインとの併用は避けてください。

更新時は4ファイルを置き換えてプラグインを再読み込みし、診断コマンドのビルド番号が `0.18.1` であることを確認します。
**設定とバックアップ管理情報を含む `data.json` は削除しないでください。**
Androidでも同じ保管庫内へ配置します。
隠しフォルダーの表示と `.obsidian` の同期対象を確認し、設定フォルダー名を変えている場合はその名前に読み替えてください。

## 基本操作

開いた直後は編集モードで、ボード全体を表示します。
保存されたPureRefのカメラ位置は復元しません。
`[[board.pur]]` のリンクから開けますが、`![[board.pur]]` のノート内埋め込みは未対応です。

| 操作 | 動作 |
|---|---|
| 画像をクリック／タップしてドラッグ | 選択画像を移動 |
| グループをクリック／タップ | グループ全体を選択 |
| グループをダブルクリック | その内部の編集階層へ入る |
| `Ctrl` / `Cmd` を押して画像をクリック | 選択に追加／選択から解除（編集モードのみ） |
| `Shift` を押して空白からドラッグ | 範囲に重なる画像を選択（編集モードのみ） |
| 空白のドラッグ、マウス中央ボタン | ボードを移動 |
| 2本指のピンチ、ホイール | 拡大縮小 |
| 選択枠の8個の丸ハンドル | 対向点を固定した等比拡縮 |
| 選択枠の四隅の外側をドラッグ | 自由回転（修飾キー不要、角度スナップなし） |
| 右クリック、長押し（650ms）、ヘッダーのPUR操作、ビューのメニュー | カテゴリ別の操作メニュー |
| ボード上で `0` / `+` / `-` / 矢印キー | 全体表示／拡大／縮小／移動 |
| PURビューで `Ctrl+S` / `Cmd+S` | 現在のPURを上書き保存 |
| 編集モードで `Ctrl+Z` / `Ctrl+Y`（macOSはCmd） | Undo／Redo |

操作メニューは「画像の追加」「編集」「整列」「グループ」「表示」「保存」の6分類です。
カテゴリをクリック／タップして子メニューへ進み、「PUR操作へ戻る」で分類一覧に戻ります。
ホバーで開く方式ではなく、公開APIのクリック操作を使い、ネストは1段だけです。
子メニューと戻る操作は最初の表示アンカーを保持し、画面端の位置補正はObsidianに任せます。
ビューのメニューは公開APIで初回位置を取得できないため、子以降はCanvas左上を基準にします。
90度回転と反転、Undo／Redo、削除は「編集」、階層移動と背景色は「グループ」にあります。
「表示」→「閲覧モードへ」に切り替えると画像上のドラッグもボード移動になります。
どちらのモードでも2本指操作は画像ではなくボードを動かします。
グリッドは画像の背面に表示し、保存データへ焼き込みません。

「選択時に最前面へ移動」は標準オンで、「表示」から変更できます。
前面化も保存とUndoの対象です。
前面化後に画像を移動した場合、Undoは移動、前面化の順に戻します。
拡縮は1操作につき開始時の0.05～20倍で、対向点を越えても反転しません。
選択枠は画像項目の矩形で、切り抜きの輪郭には沿いません。

### 複数選択と整列

選択済み画像を通常クリックすると選択集合を保ち、ドラッグでは全選択画像を同じ距離だけ移動します。
未選択画像の通常クリックはその1枚への選択に切り替え、空白の通常クリックまたは `Escape` で解除します。
Ctrl／Cmdによる選択切替と複数選択中のドラッグでは前面化せず、画像同士の重なり順を保ちます。
`Shift`＋空白ドラッグは、変換後の画像矩形が少しでも範囲に重なる画像を選び、現在の選択を置き換えます。
切り抜きの輪郭は使わず、回転画像の外接矩形だけが重なっている場合は選びません。
ドラッグ中は破線の範囲を表示し、離した時点で選択を確定します。
キャンセルや2本指操作への切替では範囲選択を適用しません。
通常の空白ドラッグは従来どおりパンです。

複数選択では集合全体を囲む共通枠に8個の拡縮ハンドルを表示します。
対向ハンドルを固定し、画像同士の相対位置と縦横比を保って等比拡縮します。
四隅外側でカーソルが変わる位置をドラッグすると、共通枠の中心を軸に集合全体が回転します。
回転ハンドル自体は描きません。
枠と操作域も回転し、続けてその向きで拡縮できます。
メニューの90度回転も集合全体に適用し、反転は1枚選択時だけ利用できます。
共通枠の向きは保存対象ではなく、選択変更、Undo／Redo、整列などで画像配置が変わると外接矩形から再計算します。
複数選択中も2本指操作はカメラ移動とズームになり、選択を保ちます。
等間隔配置は未対応です。

2枚以上選ぶと、右クリック、長押し、PUR操作メニューの6種類の整列を使えます。
「左端揃え」「右端揃え」「上端揃え」「下端揃え」は、回転と拡縮を反映した外接矩形を全選択画像の集合境界に揃えます。
「水平中央揃え」は横方向の中心（X座標）、「垂直中央揃え」は縦方向の中心（Y座標）を集合境界の中心に揃えます。
切り抜き後の輪郭ではなく画像矩形を使い、回転と倍率は変えず平行移動だけ行います。
一括移動、拡縮、回転、整列、複数画像の削除はそれぞれ1回のUndo／Redoで戻せます。
選択集合はファイルには保存しません。

コマンドパレットにも保存、Undo／Redo、全体表示、PUR操作メニューがあります。
操作コマンドはアクティブなPURビューだけが対象で、入力欄や他ビューの保存と貼り付けは横取りしません。
標準保存のキー設定は残し、PUR専用保存コマンドへの `Ctrl+S` / `Cmd+S` の重複割当は避けてください。
PUR内の保存キーは固定で、標準保存のキー変更には追従しません。

### グループの編集

v0.17.0からは、通常クリックでグループ全体を選び、ダブルクリックで内部を編集する方式です。
タブレットでは長押しまたはPUR操作メニューの「グループの内部を編集」を使えます。
内部では画像を直接編集でき、入れ子のグループにも同じ方法で入ります。
「親の階層へ戻る」で1段戻れます。
`Escape` は選択解除になり、選択がないときは親へ戻ります。
グループ外の項目を編集するときは先に親へ戻ってください。

現在の階層にある画像とグループを複数選択し、移動、共通ハンドルでの等比拡縮、回転、整列ができます。
前面化は同じ親の中だけに適用し、子を前面化しても親グループの順序は変えません。
操作メニューの「選択項目をグループ化」は同じ階層の2項目以上、「選択グループを解除」は1グループが対象です。
作成と解除はワールド配置と元画像を保ち、解除した子は元グループの重なり位置に並びます。
グループ化は選択内の最前面の位置へまとめ、選択項目同士の順序を保ちます。
間に未選択項目がある場合、その項目との前後関係が変わることがあります。
背景色変更、グループの変換、作成、解除、削除はそれぞれUndo／Redoと保存の対象です。
グループを削除すると対応する子全体も削除し、最後の画像だけを消した場合は空グループを保持します。
画像の追加はグループ外の最前面に行い、編集階層もルートへ戻します。

背景は子のローカル外接矩形に余白と角丸を付け、子より背面に描画します。
余白と角丸は提供サンプルと画面比較に基づく近似で、PureRefの全設定との一致は保証しません。
「グループ背景色を変更」で色を選び、「既定色に戻す」で未指定にできます。
未指定色はプラグインの既定色（暗い灰色）で表示し、色を変更しない限り元のnull値を保持します。
画像内変換と切り抜き、原画像データはそのまま残し、親ローカル座標で保存します。
不透明度とロックは確認済み設定（`opacity=1`、`locked=0`、`lock_mode=1`）だけが対象で、それ以外は警告して省略します。
選択外のノートと描画は表示せず元の行を保持し、対応画像のグループ操作を妨げません。
未対応の子要素を含むグループの編集、未知のテーブルや未確認の項目、コメント参照があるPURでの構造操作は安全のため拒否します。
未表示項目が同じ階層にあり、重なり順の衝突や数値間隔の不足で安全に解除できない場合も通知して拒否します。
省略した元データを無断で削除することはありません。

## 画像の追加と削除

編集モードで次の方法を使えます。
PUR未読込時と閲覧モードでは追加メニューを無効にします。

| 追加方法 | 配置 |
|---|---|
| `Ctrl+V` / `Cmd+V`、メニューの「クリップボードから貼り付け」 | ビュー中央 |
| OSから画像ファイルをドロップ | ドロップ位置 |
| 「ストレージから画像を読み込む」（システムファイル選択） | ビュー中央 |
| 「保管庫から画像を追加」（画像検索） | ビュー中央 |

複数選択した画像は順に最前面へ追加し、各画像を1回のUndoとして記録します。
不正な画像は通知してスキップし、残りの画像を処理します。
通常のテキスト、HTTP URL、HTMLからの画像取得は行いません。
SVGデータURLは貼り付けられます。

削除は「選択した画像を削除」またはボード上の `Delete` / `Backspace` です。
追加と削除はUndo／Redo、自動保存、上書き保存、別名保存に反映します。
削除を保存した後も、同じビューのUndoで復元して再保存できます。
保管庫やストレージの元画像ファイルは変更も削除もしません。

### 元データとクリップボード

**実際に受信した画像のバイト列と形式を変えずに埋め込みます。**
既存PUR内の画像も再圧縮せず、表示用の画素を保存データへ置き換えません。
GIF／WebPの後続フレーム、HEICの他画像とメタデータも元ファイルのまま保持します。

クリップボードはOS、ブラウザー、コピー元アプリが変換済みPNG等を返す場合があります。
同じ項目で複数の対応形式が提供されれば非PNGを優先しますが、元形式や元ファイルとの完全一致は保証できません。
元ファイルを取り込む場合はファイルドロップ、ストレージ選択、保管庫選択を使ってください。
過去に変換保存されたPNGから元形式を復元する機能はありません。

メニューの貼り付けは項目を押した直後にClipboard APIを呼びます。
端末によってセキュアコンテキスト、フォーカス、権限、直前の操作やOSの貼り付け確認が必要です。
非対応、拒否、対応画像なし、読取失敗は通知し、クリップボードの監視や権限の迂回は行いません。
システム選択のキャンセルでは画像を追加せず、ビューが変わった後の結果は別のPURへ取り込みません。
古いWebViewでキャンセル通知がない場合は、次の選択またはビュー終了時に選択要素を除去します。
OS選択要求が無反応で無視される場合は、JavaScriptから失敗を確定できません。

## 対応形式と制限

表示対象はルート階層と対応グループ内の埋め込み画像です。
移動、拡縮、回転、反転、せん断、不透明度、重なり順、直線と3次ベジェによる既存の切り抜きを読み取ります。

| 形式 | 表示と制限 |
|---|---|
| PNG／JPEG | 端末の画像デコーダーを使用 |
| GIF／WebP | 先頭フレームだけを静止表示。保存された再生フレームとの一致は保証しない |
| BMP | 一般的なDIBヘッダーに対応。圧縮方式と32bitアルファは端末依存 |
| SVG | UTF-8の静的SVG。図形、文字、内部グラデーション、クリップ、マスク、単純な内部参照 |
| HEIC／HEIF | HEVC静止画像の主画像を表示。時系列シーケンス、AVIF、非HEVC符号化は未対応 |

SVGは正の数値／px寸法または `viewBox` が必要で、要素数は10000以下です。
スクリプト、イベント属性、CSS、外部参照、画像埋め込み、`foreignObject`、アニメーション、フィルター、DOCTYPE、実体宣言、再帰参照は拒否します。
未対応内容を黙って削除せず、外部データも取得しません。
データURLはBase64またはパーセント符号化に対応し、文字コード指定は省略または `charset=utf-8` です。
文字の見た目は端末のフォントに依存します。

HEICは同梱のWASMデコーダーを単一Workerで実行します。
Worker／WASMが端末の制限で利用できない場合だけ、通知して従来の純JavaScript方式へ切り替えます。
画像破損、メモリー不足、寸法違反、起動タイムアウト、実行エラーでは切り替えず失敗を通知します。
Workerは処理完了と終了時に破棄し、中断時は実行中Workerを停止します。
従来方式では同期展開によるUI停止と内部ヒープの保持が残ります。
表示は8bit RGBAで、HDR、ICC、広色域の見た目を保証しません。

ノート、テキスト、描画ストローク、外部リンク画像、動画、未知の項目や画像フラグは未対応です。
省略した要素は診断に警告を残し、保存時には保持します。
壊れた変換、射影変換、不正な切り抜きや画像デコード失敗は、ボード全体の読込エラーになります。

| 上限 | 値 |
|---|---|
| PURと保持する画像データ | 64 MiB |
| 1画像 | 40MP |
| 展開画像の合計（複製とUndo資源を含む） | 80MP |
| 画像と画像項目 | 各10000件 |
| 全階層の項目／グループの深さ | 20000件／64段 |
| Canvas | 長辺4096px、デバイス倍率2倍まで |

画像を削除しても、Undo資源は再読込または終了まで残るため追加枠は増えません。
保存寸法と実寸が異なる画像は拒否します。
上限内でもSQLite、デコーダー、Canvas、保存用コピーが別途メモリーを使い、端末の確保成功は保証できません。
大きなボードでは読込待ちやメモリー不足が起こり得るため、最初は小さなファイルで確認してください。

## 保存と編集履歴

通常保存は現在のPURを上書きします。
自動保存は操作を止めてから初期値3秒で実行し、設定で1～60秒に変更できます。
設定保存の失敗は通知し、未確認の値を適用しません。
失敗した保存を保存済み扱いにせず、無限に再試行しません。

保存成功後もUndo／Redo履歴は残ります。
保存中の追加編集は未保存として残し、後で自動保存します。
「変更を破棄」は最後の上書き保存時（未保存なら読込時）の状態へ戻します。
別名保存は元ファイルと同じフォルダーに新規作成し、既存ファイルを上書きしません。
別名保存後も元ファイルのビュー、履歴、元ファイルに対する未保存状態を維持します。

保存前に元ファイルの内容、改名、削除、ビュー切替を照合し、競合時は保存を止めます。
同じプラグイン内の同一パスへの同時保存も拒否します。
**外部アプリや同期処理との競合を完全に排除する保証はありません。**
保存中は元ファイル、復旧用コピー、プラグイン設定を他アプリや他端末から変更しないでください。

保存は元DBを複製し、対応項目の配置、背景色、追加／削除、グループの親子関係だけを更新します。
未編集の画像データ、未知のテーブルと列、SQL値と保存型は保持しますが、DB全体のバイト一致は保証しません。
未知の参照を壊す可能性があれば画像データ行を残し、子要素付き画像やトリガー付きDBなど安全に編集できないものは拒否します。
サムネイル、保存カメラ、シーン範囲などは再生成しないため、PureRefのプレビューや初期表示が旧配置のままになる場合があります。
出力はメモリー内で再解析し、書込後にも読み戻して照合します。
不完全な別名出力が残った場合は自動削除しないため、通知された保存先を確認してください。

タブ終了時にも最終保存を試みますが、ObsidianやOSが完了まで待つ保証はありません。
標準のタブ閉鎖、アプリ終了、クラッシュでは破棄確認も保証できません。
終了時保存に頼らず、閉じる前に保存完了を確認してください。
確認を伴って閉じる場合は、PUR操作メニューの「ビューを閉じる」を使います。

### バックアップと復旧

上書き前に同じフォルダーへ `元ファイル.pur.lazyref-managed-ランダムID.bak` を作成し、内容と管理情報の保存を確認します。
この段階に失敗した場合は元ファイルを書き換えません。
バックアップは今回の新出力ではなく、書込前のファイル全体です。

正常保存後は登録済みの古い管理コピーだけを照合して削除し、直前の1世代を保持します。
保存中は通常2世代分の空き容量が必要です。
書込失敗、部分書込、競合、整理失敗では復旧用コピーを残すため、1世代を超える場合があります。
「保存完了、整理未完了」は、ファイル保存の成功とコピー整理の失敗を分けた通知です。
不明なコピーや変更されたコピーは削除しません。

復旧用コピーは自動復元しません。
編集と同期を止め、現在のPURも退避してから `.bak` をコピーし、別名の `.pur` にして開いてください。
コピーを含むフォルダーや元PURの改名はプラグイン有効中に追跡しますが、他端末や無効中の改名は追跡できません。
管理情報の競合や保存失敗があれば、`data.json` とコピーを退避して通知を確認します。
管理対象外の旧 `.lazyref-ランダムID.bak` は自動整理しません。
自分で対応するPURと内容を確認したコピーだけを整理し、不明な `.bak` をまとめて削除しないでください。
